Claude 모델, 뭘 골라야 할까 — 앤트로픽 공식 모델 선택 가이드 한국어 정리

내 일에 맞는 Claude 모델을 고르고, 모델을 바꾸기 전에 비용부터 줄이는 순서를 알게 됩니다.

준비물

  • Claude 앱 또는 Claude API 계정
  • 내가 맡기려는 일 한두 가지 (실제 자료로 시험해 볼 것)
  • 읽는 데 5분

순서

1

고르기 전에 기준 네 가지부터 정한다

앤트로픽은 모델을 고를 때 네 가지를 먼저 보라고 합니다. 어떤 능력이 필요한지, 답이 얼마나 빨리 와야 하는지, 예산이 얼마인지, 그리고 effort(생각을 얼마나 깊게 할지) 설정입니다. 특히 effort는 모델을 바꾸는 것보다 먼저 만져볼 손잡이라고 강조해요. 같은 모델 안에서 속도·비용과 똑똑함을 맞바꿀 수 있기 때문입니다.

✓ 내 일에 대해 '능력 / 속도 / 예산' 중 무엇이 제일 중요한지 한 줄로 적을 수 있다.

2

모델 선택표에서 출발점을 고른다

공식 가이드의 선택표입니다. 가장 높은 능력이 필요하면 Claude Fable 5.1: 몇 시간짜리 에이전트 작업, 여러 단계의 깊은 리서치, 문서·표·슬라이드까지 끝내는 분석. 복잡한 코딩·기업 업무는 Claude Opus 5.5: 몇 시간씩 스스로 도는 코딩 에이전트, 대규모 코드 정리, 화면을 많이 보는 작업, 컴퓨터 조작. 매일 하는 코딩·에이전트·업무를 빠르게는 Claude Sonnet 5.5: 코드 작성, 데이터 분석, 글·콘텐츠 작성, 이미지 이해, 도구 사용. 가장 빠르고 싸게는 Claude Haiku 4.5: 실시간 앱, 대량 처리, 하위 에이전트 작업. 가이드는 대부분의 작업이 Opus 5.5에서 출발한다고 적고 있어요.

claude-fable-5-1
claude-opus-5-5
claude-sonnet-5-5
claude-haiku-4-5

✓ 내 일이 표의 네 줄 중 어디에 가장 가까운지 하나를 골랐다.

3

출발 방식을 정한다: 가볍게 시작 vs 강하게 시작

방법이 두 가지입니다. 가볍게 시작하기는 Haiku 4.5로 만들어 보고, 모자란 부분이 확인될 때만 올리는 방식이에요. 시제품, 빠른 응답이 중요한 앱, 예산이 빠듯한 일, 단순한 대량 작업에 맞습니다. 강하게 시작하기는 Opus 5.5로 먼저 제대로 되게 만든 뒤, effort를 낮추거나 모델을 내리며 비용을 줄이는 방식이에요. 복잡한 추론, 과학·수학, 정확도가 비용보다 중요한 일, 고급 코딩에 맞습니다. Opus 5.5에서 effort를 최대로 올려도 부족하면 그때 Fable 5.1로 갑니다.

✓ '가볍게 시작' 또는 '강하게 시작' 중 하나를 골랐다.

4

모델을 바꾸기 전에 effort부터 조절한다

Opus 5.5의 기본 effort는 medium이고, 거기서 시작해 결과를 보며 올리거나 내리라고 안내합니다. Sonnet 5.5는 발표 글 기준으로 Claude Code와 Claude 앱에서 Medium, Claude API에서는 High가 기본값이에요. 낮추면 답이 빨라지고 토큰을 덜 쓰니 반복 업무에 맞고, 올리면 더 오래 생각하고 스스로 한 번 더 검토합니다. 발표 글의 차트에서도 Sonnet 5.5는 Medium 설정만으로 이전 모델 Sonnet 5의 최고 점수를 훨씬 적은 비용으로 넘었습니다.

✓ 같은 일을 effort만 바꿔 두 번 돌려 보고 결과·속도 차이를 확인했다.

5

내 실제 자료로 비교 시험을 한다

가이드가 가장 중요하다고 꼽는 단계입니다. 내 일에 맞는 시험 문제를 만들고, 실제로 쓸 프롬프트와 자료로 모델 몇 개를 돌려 봅니다. 답의 정확도, 답의 질, 까다로운 예외를 어떻게 처리하는지를 비교한 뒤 성능과 비용을 함께 따져 정합니다.

✓ 같은 문제 5~10개를 두 모델에 돌려 나란히 비교한 결과가 있다.

6

필요하면 모델을 섞어 쓴다

싼 모델과 최상위 모델을 짝지으면 토큰 대부분을 싼 값에 쓸 수 있습니다. 흔한 방식은 두 가지예요. 싼 모델이 일을 하다가 어려운 판단만 위 모델에게 묻는 방식, 그리고 위 모델이 계획을 짜고 대량 작업은 싼 모델들에게 나눠 주는 방식입니다. 발표 글의 한 테스터도 'Opus 5.5가 게임 구조를 잡으면 구현은 Sonnet 5.5에게 맡기겠다'고 했어요.

✓ 내 일에서 '어려운 판단'과 '반복 작업'을 나눠 적어 봤다.

여기서 막힙니다

Sonnet 5.5로 바꿨더니 thinking을 끄고 쓰던 설정이 예전처럼 안 돈다

발표 글 안내: thinking을 끄고 Sonnet을 쓰던 경우 Sonnet 5.5로 옮기기 전에 새 설정 between_tools로 바꿔야 합니다. 공식 이전 가이드(migration guide)를 확인하세요.

Opus 5.5로 옮겼는데 도구 강제 호출이나 컴퓨터 조작 설정에서 오류가 난다

Opus 5.5는 생각 기능이 항상 켜져 있습니다. 도구 사용을 강제하거나(tool_choice any/tool), thinking을 끄거나, computer_20251124 도구를 쓰는 경우 공식 문서의 Breaking changes를 먼저 확인하라고 안내합니다.

fast mode를 켰더니 비용이 올랐다

fast mode는 Opus 5.5 등에서 출력 속도를 최대 2.5배 올리는 연구 미리보기 기능인데, 대신 더 비싼 요금이 붙습니다. 속도가 꼭 필요할 때만 켭니다.

바꿔볼 것

  • 지금 Opus로 돌리는 반복 업무 하나를 골라 Sonnet 5.5 Medium으로 돌려 보고 결과를 비교해 보세요. 값은 Opus 5.5의 절반입니다.
  • 코딩이라면 계획은 Opus 5.5, 구현은 Sonnet 5.5로 나눠 보세요.
