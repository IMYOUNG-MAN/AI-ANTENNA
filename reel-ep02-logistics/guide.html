서버 터졌다, 물류센터로 풀기

"서버 터졌다"는 말부터 배포·다운타임까지, 뉴스와 AI 화면에 뜨는 말이 그림으로 그려져요.

전체 흐름

  1. 요청 — 내가 누른 버튼이 인터넷을 타고 저쪽 컴퓨터로 넘어가요
  2. 트래픽 — 그 요청이 한꺼번에 몰리면 양이 확 커지죠
  3. 로드밸런서 — 입구에서 여유 있는 서버로 요청을 나눠 보내요
  4. 서버 — 요청을 받아 처리하고 답을 만들어 돌려줘요
  5. 캐시 — 자주 나가는 답은 미리 꺼내 두고 바로 건네요
  6. 스케일 아웃 — 그래도 모자라면 서버 대수를 늘려요
  7. 배포 — 고친 코드를 실제 서비스에 올려서 돌려요
  8. 다운타임 — 그 사이 서비스가 멈춰 있던 시간이에요
서버트래픽로드밸런서스케일 아웃캐시배포다운타임

1. 서버

한 줄로 · 주문 오면 물건 꺼내서 보내주는 물류센터
실제로는

서버는 요청을 받아서 처리하고 결과를 돌려주는 컴퓨터예요. 내 노트북처럼 생긴 기계지만 끄지 않고 계속 켜 둔 채, 전 세계에서 들어오는 요청을 받는 역할만 맡죠. 챗GPT도 클로드도 답을 내 컴퓨터가 아니라 저쪽 서버가 만들어 보내줘요.

이렇게 작동해요
  1. 내 브라우저나 앱이 요청을 보낸다
  2. 요청이 인터넷을 타고 서버에 닿는다
  3. 서버가 계산하거나 저장된 자료를 찾는다
  4. 결과를 다시 내 쪽으로 돌려보낸다
  5. 내 화면에 답이 뜬다
AI 쓸 때 여기서 만나요

클로드나 챗GPT에서 "지금 사용량이 많습니다", "Overloaded" 같은 말이 뜰 때가 바로 서버가 벅찬 순간이에요. 내 인터넷이 아니라 저쪽 컴퓨터가 밀린 거죠.

예를 들면

새벽에 물어보면 1초 만에 글자가 쏟아지는데, 저녁 9시엔 커서만 깜빡이죠. 같은 질문, 같은 노트북인데 속도가 다르다면 거의 서버 쪽 사정이에요.

써먹는 요령

답이 안 나올 때 와이파이부터 의심하기보다, 서비스 상태 페이지를 먼저 보세요. 저쪽 문제면 기다리는 게 제일 빠른 해결이에요.

✓

해보기 · AI한테 내 질문의 여행 경로를 그려 달라고 하기

내가 엔터를 누른 뒤 답이 돌아올 때까지 뭘 거치는지 물어보세요. 서버라는 말이 어디에 끼는지 한 번에 잡혀요.

내가 챗봇에 질문을 쓰고 엔터를 누르면 답이 돌아올 때까지 어떤 단계를 거치나요? 코딩 모르는 사람이 알아듣게 5단계로, 서버가 어디서 끼어드는지 표시해서 설명해 주세요.

2. 트래픽

한 줄로 · 그 센터로 오늘 쏟아지는 상자 백만 개
실제로는

트래픽은 정해진 시간 동안 서버로 오고 가는 요청과 데이터의 양이에요. 사람 수가 아니라 요청 횟수와 주고받은 자료 크기로 셉니다. 트래픽이 많아지면 서버가 줄을 세우기 시작하고, 그래서 느려지거나 일부 요청은 아예 실패하죠.

이렇게 작동해요
  1. 사람들이 같은 시간에 버튼을 누른다
  2. 요청이 서버로 한꺼번에 몰린다
  3. 서버가 처리할 수 있는 양을 넘으면 대기줄이 생긴다
  4. 응답이 느려지거나 일부가 실패한다
  5. "요청이 너무 많습니다" 같은 안내가 뜬다
AI 쓸 때 여기서 만나요

AI의 API를 쓰다 보면 "rate limit", 우리말로 사용 한도를 넘었다는 메시지를 만나요. 한 사람이 짧은 시간에 너무 많이 보내는 걸 막는 장치인데, 트래픽을 숫자로 관리한다는 뜻이거든요.

예를 들면

오전엔 잘 돌던 자동화가 점심시간에만 중간에 끊긴다면 사람이 몰리는 시간대를 탄 거예요. 한 번에 글 50개를 쭉 돌리면 앞쪽 몇 개만 되고 뒤는 "잠시 후 다시 시도"가 뜨기도 하죠.

써먹는 요령

많은 걸 한꺼번에 돌리지 말고 몇 개씩 나눠서, 사이에 몇 초 쉬어 가며 보내세요. 실패하면 조금 기다렸다 다시 보내는 게 기본 요령이에요.

✓

해보기 · 한도 걸렸을 때 쓸 문장 만들어 두기

AI에게 내 상황을 주고, 어느 정도 속도로 나눠 돌리면 좋은지 물어보세요. 다음에 똑같은 메시지를 만나도 안 당황해요.

AI 서비스를 쓰다가 "요청이 너무 많습니다"라는 메시지를 봤어요. 왜 이런 게 뜨는지, 작업을 몇 개씩 나눠 몇 초 간격으로 돌리면 좋은지 코딩 모르는 사람 기준으로 알려 주세요.

3. 로드밸런서

한 줄로 · 입구에 선 반장이 상자를 빈 컨베이어로 쪽쪽 나눠주는 일
실제로는

로드밸런서는 들어오는 요청을 여러 서버에 나눠 보내는 역할이에요. 사용자는 주소 하나만 아는데, 그 뒤에서 요청이 서버 여러 대로 흩어지죠. 한 대가 죽으면 명단에서 빼고 살아 있는 서버로만 보내서, 한 대 고장이 서비스 전체 중단으로 번지지 않게 막아줘요.

이렇게 작동해요
  1. 요청이 서비스 주소 하나로 도착한다
  2. 로드밸런서가 서버들의 상태를 확인한다
  3. 여유 있는 서버 한 대에 요청을 넘긴다
  4. 그 서버가 만든 답을 사용자에게 전달한다
  5. 응답이 없는 서버는 명단에서 빼 둔다
AI 쓸 때 여기서 만나요

Claude Code나 Cursor에 "사람이 많이 쓰면 어떻게 버티게 하죠?"라고 물으면 답에 꼭 나오는 말이에요. 클라우드에 올릴 때 설정 화면에서도 만나게 되죠.

예를 들면

같은 시간에 새로고침을 두 번 했는데 한 번은 되고 한 번은 안 되는 일이 있어요. 한쪽 서버만 상태가 안 좋고 요청이 그 대로 갔을 때 그렇게 보이거든요.

써먹는 요령

작은 서비스를 만들 땐 직접 챌 일이 거의 없어요. 요즘 배포 서비스들이 이 역할을 알아서 해주니, "내가 설정할 게 있나?"만 AI에게 확인하면 충분해요.

✓

해보기 · 서버 두 대 구조를 말로 설명받기

그림 없이도 머리에 남게, 비유를 바꿔 설명해 달라고 해보세요. 한 대만 쓸 때와 뭐가 달라지는지가 핵심이에요.

로드밸런서가 뭔지 식당이나 공항 비유로 설명해 주세요. 서버를 한 대만 쓸 때와 두 대로 나눌 때 사용자 입장에서 뭐가 달라지는지도 같이요.

4. 스케일 아웃

한 줄로 · 넘치면 똑같은 센터를 옆에 하나 더 짓기
실제로는

스케일 아웃은 서버 대수를 늘려서 처리량을 키우는 방법이에요. 같은 구성을 복제해 여러 대로 돌리고, 앞에서 요청을 나눠 받죠. 한 대를 더 좋은 사양으로 바꾸는 건 스케일 업인데, 요즘 서비스는 늘리고 줄이기가 쉬운 스케일 아웃을 더 많이 씁니다.

이렇게 작동해요
  1. 서버 한 대가 감당할 양을 넘긴다
  2. 같은 서버를 복제해서 한 대 더 띄운다
  3. 로드밸런서 명단에 새 서버를 올린다
  4. 요청이 두 대로 나뉘어 들어간다
  5. 한가해지면 다시 한 대로 줄인다
AI 쓸 때 여기서 만나요

Claude Code로 만든 서비스를 클라우드에 올릴 때 "인스턴스 수" 같은 칸을 보게 돼요. 거기 숫자를 2로 올리는 게 바로 스케일 아웃이에요.

예를 들면

평소엔 서버 한 대로 충분한데 이벤트 날만 사람이 열 배 몰린다면, 그날만 서버를 네 대로 늘렸다가 다음 날 되돌리죠. 요금도 켜 둔 만큼만 나가니까 이렇게 쓰는 거예요.

써먹는 요령

처음부터 크게 지을 필요는 없어요. 작게 시작해 두고, 느려지는 게 보일 때 늘리는 순서가 돈도 시간도 아껴줘요.

✓

해보기 · 내 서비스에 필요한 때를 물어보기

만들려는 걸 한 줄로 적고, 언제쯤 서버를 늘려야 하는지 물어보세요. 기준이 생기면 불필요한 걱정이 줄어요.

제가 만들려는 건 (여기에 한 줄로 적기)예요. 서버를 한 대로 시작해도 되는지, 몇 명쯤 쓰기 시작하면 대수를 늘려야 하는지 코딩 모르는 사람 기준으로 알려 주세요.

5. 캐시

한 줄로 · 제일 많이 나가는 물건은 문 앞에 미리 쌓아두기
실제로는

캐시는 자주 쓰는 결과를 가까운 곳에 잠깐 저장해 두고 다시 꺼내 쓰는 방식이에요. 매번 처음부터 계산하거나 멀리서 가져오지 않으니 훨씬 빠르죠. 대신 원본이 바뀌었는데 캐시가 그대로면 옛날 내용이 보여요. 그래서 "캐시를 지워 보세요"라는 말이 나오는 거예요.

이렇게 작동해요
  1. 요청이 들어온다
  2. 캐시에 이미 같은 답이 있는지 본다
  3. 있으면 계산 없이 그대로 돌려준다
  4. 없으면 원본에서 만들어 주고, 캐시에도 넣어 둔다
  5. 같은 요청이 다음에 오면 바로 나간다
AI 쓸 때 여기서 만나요

AI를 쓸 때는 두 군데서 만나요. 하나는 웹 화면이 옛날 상태로 멈춰 보일 때 브라우저 캐시, 또 하나는 긴 지시문을 매번 다시 읽지 않게 앞부분을 저장해 두는 프롬프트 캐싱이에요.

예를 들면

AI 서비스에서 설정을 바꿨는데 화면엔 그대로 옛 값이 보이는 일이 있죠. 강력 새로고침 한 번에 제대로 뜨면, 바뀐 걸 못 받고 저장된 걸 보고 있었던 거예요.

써먹는 요령

화면이 이상하면 먼저 강력 새로고침, 그다음 다른 브라우저나 시크릿 창으로 열어보세요. 둘 다에서 똑같이 이상하면 그건 캐시가 아니라 저쪽 문제예요.

✓

해보기 · 강력 새로고침 한 번 눌러보기

지금 열어 둔 AI 화면에서 눌러보세요. 저장된 화면이 아니라 새 화면을 받아오는 단축키예요.

윈도우: Ctrl + Shift + R / 맥: Cmd + Shift + R

6. 배포

한 줄로 · 새 분류기를 들여와 오늘부터 진짜로 돌리는 그 순간
실제로는

배포는 고친 코드를 실제 사용자가 쓰는 곳에 올려서 돌리는 일이에요. 내 컴퓨터에서만 되던 걸 인터넷 주소로 누구나 열 수 있게 만드는 단계죠. 문제가 생기면 이전 버전으로 되돌리는데, 이걸 롤백이라고 불러요.

이렇게 작동해요
  1. 코드를 고친다
  2. 내 컴퓨터에서 제대로 되는지 확인한다
  3. 실제 서비스 쪽에 새 버전을 올린다
  4. 주소로 들어오는 사람들이 새 버전을 쓰게 된다
  5. 문제가 보이면 이전 버전으로 되돌린다
AI 쓸 때 여기서 만나요

Claude Code나 Cursor로 웹페이지를 하나 만들면 꼭 듣는 말이에요. "내 컴퓨터에서는 되는데 친구한테 보여주려면?" 하고 물으면 "배포하세요"라는 답이 돌아오죠.

예를 들면

링크를 보냈는데 친구가 "안 열려요"라고 하면 보통 배포를 안 한 거예요. localhost로 시작하는 주소는 내 컴퓨터 안에서만 통하는 주소거든요.

써먹는 요령

되돌릴 방법을 먼저 확인하고 올리세요. "문제 생기면 어떻게 전 버전으로 돌리나요?"를 AI에게 물어 두면 마음이 훨씬 편해요.

✓

해보기 · 내 페이지 올리는 길 물어보기

AI에게 가장 쉬운 방법을 단계로 받아 보세요. 되돌리는 법까지 같이 물어두면 좋아요.

제가 만든 간단한 웹페이지를 친구가 링크로 열어볼 수 있게 인터넷에 올리고 싶어요. 무료로 할 수 있는 가장 쉬운 방법을 단계별로, 그리고 문제가 생겼을 때 이전 상태로 되돌리는 방법도 알려 주세요.

7. 다운타임

한 줄로 · 기계 바꾸는 동안 센터가 멈춰 있는 시간
실제로는

다운타임은 서비스가 멈춰서 쓸 수 없는 시간이에요. 갑작스런 장애로 멈출 때도 있고, 점검하려고 일부러 멈출 때도 있죠. 요즘은 서버를 여러 대 두고 하나씩 돌아가며 새 버전으로 바꿔서, 멈추는 시간 없이 배포하기도 해요.

이렇게 작동해요
  1. 장애가 생기거나 점검이 시작된다
  2. 들어오는 요청이 실패하기 시작한다
  3. 회사가 상태 페이지에 상황을 올린다
  4. 원인을 고치고 서버를 다시 띄운다
  5. 서비스가 돌아오고, 멈춰 있던 시간이 기록으로 남는다
AI 쓸 때 여기서 만나요
