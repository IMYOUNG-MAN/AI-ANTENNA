1. 서버

비유로 치면 · 주문 오면 물건 꺼내서 보내주는 물류센터
실제로는

서버는 남의 요청을 받아 처리하고 결과를 돌려주는 컴퓨터예요. 내 노트북처럼 생긴 기계인데, 꺼지지 않게 켜둔 채 인터넷에 연결해 둔 거죠. 챗GPT나 클로드에 질문을 던지면 계산은 내 컴퓨터가 아니라 저쪽 서버가 해요.

이렇게 작동해요
  1. 내가 질문을 쓰고 엔터를 누른다
  2. 그 문장이 인터넷을 타고 서버로 간다
  3. 서버가 모델을 돌려 답을 만든다
  4. 만든 답이 내 화면으로 돌아온다
AI 쓸 때 여기서 만나요

클로드나 챗GPT에 긴 글을 맡겨도 내 노트북 팬은 조용해요. 무거운 계산은 전부 저쪽 서버에서 돌아가니까요. 그래서 인터넷이 끊기면 아무것도 못 해요.

예를 들면

보고서 10장을 요약시키면 30초쯤 멍하니 기다리게 되는데, 그동안 내 컴퓨터는 거의 아무 일도 안 해요. 반대로 비행기에서 와이파이 없이 열면 입력창은 뜨지만 답이 안 와요. 서버까지 말이 못 가서 그래요.

써먹는 요령

답이 안 오면 먼저 내 인터넷을 보고, 멀쩡하면 서비스 쪽 상태 페이지를 보세요. 내가 고칠 수 있는 문제와 기다려야 하는 문제가 갈려요.

지금 열어서 즐겨찾기에 넣어두면, 다음에 답이 안 올 때 1초 안에 원인을 가릴 수 있어요.

2. 트래픽

비유로 치면 · 그 센터로 오늘 상자가 백만 개 쏟아진다
실제로는

트래픽은 같은 시간에 서버로 몰려드는 요청의 양이에요. 사람이 많아지면 요청이 줄줄이 쌓이고, 서버가 한 번에 처리할 수 있는 양을 넘기면 느려지거나 아예 거절해요. 내 질문이 어려워서 느린 게 아니라 옆 사람이 많아서 느린 경우가 꽤 많습니다.

이렇게 작동해요
  1. 수많은 사람이 같은 시간에 요청을 보낸다
  2. 요청이 서버 앞에 줄을 선다
  3. 처리 한도 안이면 차례대로 답이 나간다
  4. 한도를 넘으면 느려지거나 '지금은 안 된다'는 응답이 돌아온다
AI 쓸 때 여기서 만나요

새 모델이 공개된 날 유독 답이 느리거나 '사용량이 많다'는 안내가 뜨죠. 그게 트래픽이 몰린 상태예요.

예를 들면

평소엔 5초에 나오던 답이 저녁에 20초씩 걸리는 날이 있어요. 같은 질문인데 아침에 다시 던지면 금방 나오거든요. 무료로 쓰는 쪽이 먼저 막히는 것도 흔한 일이에요.

써먹는 요령

느릴 때 새로고침을 연타하면 내 요청만 더 늘어나요. 1~2분 두고 다시 보내는 편이 빨라요.

✓

해보기 · 같은 질문, 시간대 바꿔 던져보기

지금 한 번, 이른 아침이나 늦은 밤에 한 번 같은 질문을 넣어 보세요. 답 나오는 속도가 눈에 띄게 달라지는 걸 직접 느낄 수 있어요.

3. 로드밸런서

비유로 치면 · 입구에 선 반장이 상자를 빈 컨베이어로 쪽쪽 나눠준다
실제로는

로드밸런서는 들어온 요청을 여러 대의 서버에 나눠 보내 주는 중간 장치예요. 지금 한가한 서버를 골라 넘기고, 응답이 없는 서버는 명단에서 빼 버려요. 그래서 서버 한 대가 죽어도 서비스 전체가 같이 멈추지는 않죠.

이렇게 작동해요
  1. 내 요청이 서버가 아니라 로드밸런서에 먼저 닿는다
  2. 로드밸런서가 지금 여유 있는 서버를 고른다
  3. 그 서버에 요청을 넘긴다
  4. 나온 답을 나에게 돌려준다
  5. 서버 하나가 응답을 못 하면 그 서버는 빼고 돌린다
AI 쓸 때 여기서 만나요

쓰는 사람 눈에는 안 보여요. 다만 똑같은 질문인데 어떤 날은 빠르고 어떤 날은 느린 이유, 서버 몇 대가 고장 나도 서비스가 계속 열려 있는 이유가 여기 있어요.

예를 들면

대화창을 두 개 열어 동시에 질문하면 각각 다른 서버에서 처리될 수 있어요. 그래서 한쪽이 먼저 끝나기도 하죠. 이런 걸 '뒤에서 나눠 보내고 있다'고 이해하면 돼요.

써먹는 요령

접속이 이상할 때 휴대폰 데이터로 한 번 열어보세요. 거기선 멀쩡하면 내 쪽 인터넷 문제, 똑같이 안 되면 저쪽 문제예요.

✓

해보기 · 다른 네트워크로 한 번 열어보기

와이파이를 끄고 휴대폰 데이터로 같은 서비스에 접속해 보세요. 원인이 내 쪽인지 서버 쪽인지 바로 갈립니다.

4. 스케일 아웃

비유로 치면 · 그래도 넘치면 똑같은 센터를 옆에 하나 더 짓는다
실제로는

스케일 아웃은 똑같은 서버를 여러 대로 늘려서 처리량을 키우는 방법이에요. 기계 한 대를 더 좋은 걸로 바꾸는 방식도 있는데, 그건 스케일 업이라고 따로 불러요. 요즘 서비스는 사람이 몰리면 서버를 자동으로 늘리고, 한가해지면 다시 줄여요.

이렇게 작동해요
  1. 요청이 평소보다 많아진 게 감지된다
  2. 똑같은 서버를 몇 대 더 띄운다
  3. 로드밸런서가 새 서버에도 요청을 나눠 준다
  4. 한가해지면 늘린 서버를 다시 거둔다
AI 쓸 때 여기서 만나요

'지금 접속이 많아 잠시 기다려 달라'는 안내가 몇 분 뒤 풀리는 경우가 있죠. 뒤에서 서버를 더 띄우는 중일 때가 많아요. 요금제마다 동시에 쓸 수 있는 양이 정해져 있는 것도 이 비용 때문이에요.

예를 들면

출근 시간에 사람이 몰리면 서버를 10대에서 30대로 늘리고, 새벽엔 다시 줄여 돈을 아끼는 식이에요. 늘리는 데도 몇 분은 걸리니까, 폭주 직후 몇 분은 느릴 수밖에 없어요.

써먹는 요령

나도 비슷하게 쓸 수 있어요. 긴 작업을 한 창에서 끝까지 기다리는 대신, 서로 상관없는 부분은 대화창을 나눠 동시에 맡기면 전체 시간이 줄어요.

✓

해보기 · 작업을 두 창에 쪼개 맡기기

'자료 조사'와 '초안 쓰기'처럼 따로 돌아가는 일을 대화창 두 개에 나눠 넣어 보세요. 한 창에서 순서대로 기다릴 때보다 빨리 끝납니다.

5. 캐시

비유로 치면 · 제일 많이 나가는 물건은 문 앞에 미리 쌓아둔다
실제로는

캐시는 한 번 만든 결과를 가까운 데 저장해 두고 다시 꺼내 쓰는 방식이에요. 같은 걸 또 계산하지 않으니 빠르고, 돈도 덜 들죠. 대신 원본이 바뀌었는데 저장해 둔 옛 값을 돌려주면 화면이 옛날 상태로 보이는 문제가 생겨요.

이렇게 작동해요
  1. 요청이 들어온다
  2. 저장해 둔 결과가 있는지 먼저 본다
  3. 있으면 그걸 바로 돌려준다
  4. 없으면 서버가 계산하고, 그 결과를 저장해 둔다
  5. 다음번 같은 요청은 저장된 걸 쓴다
AI 쓸 때 여기서 만나요

AI에 긴 문서를 붙여 놓고 질문을 계속 이어갈 때, 앞에 붙인 그 문서를 매번 새로 읽지 않게 저장해 두는 기능이 있어요. 프롬프트 캐싱이라고 불러요. 웹에서 '캐시를 지우세요'라는 안내를 보는 것도 같은 개념이에요.

예를 들면

사내 규정 20장을 맨 앞에 붙이고 질문을 열 번 던진다고 해 보세요. 첫 질문은 느리지만 두 번째부터는 앞부분을 다시 읽지 않으니 눈에 띄게 빨라져요. 반대로 웹페이지가 분명히 바뀐 걸 아는데 옛 화면이 보이면, 브라우저가 저장해 둔 걸 보여주는 거죠.

써먹는 요령

안 바뀌는 내용(지침, 긴 문서)은 대화 맨 앞에 몰아두고, 매번 달라지는 질문은 뒤에 쓰세요. 앞부분이 그대로라 저장해 둔 걸 쓰기 쉬워져요.

✓

해보기 · 강제 새로고침 단축키 써보기

바뀐 게 안 보이는 웹페이지에서 눌러 보세요. 저장해 둔 걸 무시하고 새로 받아옵니다.

윈도우: Ctrl + Shift + R / 맥: Cmd + Shift + R

6. 배포

비유로 치면 · 새 분류기를 들여와 오늘부터 진짜로 돌린다
실제로는

배포는 새로 만든 코드를 실제 사용자가 쓰는 곳에 올려서 돌리기 시작하는 일이에요. 내 컴퓨터에서 잘 돌아가는 것과 남이 쓸 수 있는 것은 다른 단계거든요. 올린 뒤 문제가 생기면 이전 버전으로 되돌리기도 해요.

이렇게 작동해요
  1. 코드를 고친다
  2. 내 컴퓨터에서 돌려 확인한다
  3. 그 코드를 서버로 보낸다
  4. 서버가 새 버전으로 바뀌어 돌기 시작한다
  5. 문제가 터지면 이전 버전으로 되돌린다
AI 쓸 때 여기서 만나요

Claude Code나 커서로 만든 페이지는 아직 내 폴더 속 파일일 뿐이에요. 링크로 남에게 보여주려면 '이제 배포해 줘'까지 가야 하고, 그때 처음으로 주소가 생겨요.

예를 들면

AI가 만들어 준 페이지를 내 브라우저에서 열면 주소창에 localhost 같은 게 떠요. 그 주소를 친구한테 보내면 안 열립니다. 내 컴퓨터만 아는 주소라서요. 배포하면 누구나 열 수 있는 주소가 생기죠.

써먹는 요령

올리기 전에 지금 상태를 저장해 두세요. 새 버전이 망가져도 되돌릴 자리가 남아요.

Claude Code나 커서 대화창에 그대로 붙여 넣으세요. 지금 코드가 되돌릴 수 있는 지점으로 저장돼요.

지금 작업한 내용을 깃에 커밋해 줘. 커밋 메시지는 "배포 전 저장"으로 해.

7. 다운타임

비유로 치면 · 기계 바꾸는 동안 센터는 멈춰 있다
실제로는

다운타임은 서비스가 멈춰서 쓸 수 없는 시간이에요. 장애가 나서 멈추기도 하고, 점검이나 새 버전 교체 때문에 일부러 멈추기도 해요. 요즘은 새 버전을 먼저 띄워 놓고 요청을 슬쩍 옮기는 식으로, 멈추는 시간을 거의 안 만드는 방법을 많이 씁니다.

이렇게 작동해요
  1. 서버가 장애로 멈추거나, 교체하려고 꺼진다
  2. 들어온 요청이 처리되지 못한다
  3. 쓰는 사람 화면에는 오류나 점검 안내가 뜬다
  4. 고치거나 이전 버전으로 되돌린다
  5. 다시 요청을 받기 시작한다
AI 쓸 때 여기서 만나요

한창 작업하다가 갑자기 오류 메시지만 뜨고 답이 안 오는 순간이 있죠. 그게 다운타임 한가운데 있는 거예요. 상태 페이지에 보통 '장애 중'으로 표시돼요.

예를 들면

답을 받는 중에 오류가 나면 내가 길게 쓴 프롬프트까지 날아간 것 같아 아찔하죠. 상태 페이지를 보면 '일부 사용자 응답 지연' 같은 줄이 올라와 있고, 몇십 분 뒤 '해결됨'으로 바뀌어요. 그 사이엔 기다리는 수밖에 없어요.

써먹는 요령

긴 프롬프트는 메모 앱에 쓰고 복사해서 넣으세요. 오류가 나도 원문이 남아 바로 다시 보낼 수 있어요.
